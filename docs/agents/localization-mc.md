# Локализация MC

Русские строки MC хранятся в `Resources/Locale/ru-RU/` в файлах Fluent (`.ftl`). Начните с источника текста. Для имени предмета найдите `id` сущности в YAML. Для кнопки, уведомления или сообщения найдите ключ в коде или поле локализации в YAML.

## Куда положить перевод

Поищите точный ключ по всему каталогу нужного языка. Например, из корня проекта:

```sh
rg -n "^ent-MCPouchSurgeryFilled =" Resources/Locale/ru-RU
```

Если ключ уже есть, правьте найденную запись. Это касается и старого дерева `prototypes/_mc/`. При переносе записи удалите её прежнее определение, чтобы в одном языке у ключа осталось одно значение.

Для новой сущности ориентируйтесь на соседние прототипы. В новом дереве `Resources/Locale/ru-RU/_MC/entities/` каталоги повторяют структуру `Resources/Prototypes/_MC/Entities/`. Пишите имена каталогов и файлов строчными латинскими буквами, слова в новых именах разделяйте дефисом. Например, `Clothing/Belts/medical_bag.yml` соответствует `clothing/belts/medical-bag.ftl`. Родственные варианты держите в одном файле. В группах с общими базовыми прототипами встречается `_base.ftl`. [Исходный YAML](../../Resources/Prototypes/_MC/Entities/Clothing/Belts/medical_bag.yml) · [Русский FTL](../../Resources/Locale/ru-RU/_MC/entities/clothing/belts/medical-bag.ftl)

## Название, описание и варианты сущности

По умолчанию ключ сущности образуется из `ent-` и точного `id` прототипа с сохранением регистра. Справа от `=` укажите название. Нарицательное название предмета обычно начинается со строчной буквы и пишется без точки. Описание поместите в `.desc` с отступом в четыре пробела. Полное предложение начинайте с прописной буквы и завершайте точкой.

Если у варианта то же название и описание, используйте ссылки Fluent на базовую запись. В `.suffix` укажите отличие, например заполненность или роль. Так при правке перевода базового предмета обновятся все варианты, которые на него ссылаются. [Прототипы подсумка](../../Resources/Prototypes/_MC/Entities/Clothing/Pouches/Medical/surgery.yml) · [Перевод подсумка](../../Resources/Locale/ru-RU/_MC/entities/clothing/pouches/medical/surgery.ftl)

```ftl
ent-MCPouchSurgery = подсумок для хирургических инструментов
    .desc = Заметный белый медицинский подсумок, вмещающий все ваши хирургические инструменты.

ent-MCPouchSurgeryFilled = { ent-MCPouchSurgery }
    .desc = { ent-MCPouchSurgery.desc }
    .suffix = Заполнен
```

Добавляйте атрибуты по смыслу. Если переводите только название, достаточно строки `ent-… = …`. Если описание должно быть явно пустым, используйте `.desc = { "" }`. В описаниях с разметкой сохраняйте значимые выделения и парные теги, например `[bold]…[/bold]` и `[color=#ea0e4d]…[/color]`. [Пример пустого описания](../../Resources/Locale/ru-RU/_MC/entities/structures/machines/vending/nexus/engineer.ftl) · [Примеры выделения в тексте](../../Resources/Locale/ru-RU/_MC/entities/objects/medical/injectors/medical/tier1.ftl)

## Интерфейс и игровые сообщения

Группируйте строки по игровой системе в `_MC/`. Например, подписи окна выдачи снаряжения лежат в `ui/quick-equip.ftl`, а сообщения аккумулятора — в `power/powerpack.ftl`. Для нового ключа следуйте префиксу соседних строк. В этих системах принят вид `mc-<тема>-<назначение>`. Для кнопки называйте действие глаголом, для сообщения описывайте результат.

```ftl
mc-quick-equip-open = Открыть файл…
mc-quick-equip-unknown = Неизвестный предмет ({ $id })
```

Сверьте ключ и переменные с местом вызова. В этом примере C# передаёт аргумент `id`, поэтому в FTL используется `{ $id }`. Если у строки есть английская и русская версии, сохраните один и тот же ключ и имена аргументов в обеих.
